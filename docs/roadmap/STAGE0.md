# Stage 0 Spec — Trust Foundation
Goal: no gate fails silently, no score is self-graded, no prompt references a tool the runtime hasn't verified.

S0-1 Loop outcomes: NonEscalatingLoopAgent must record a typed outcome per invocation — "approved" (a confirmation agent escalated/approved), "exhausted" (max_iterations hit without approval) — into ctx.session.state["<loop_name>_outcome"], and emit a structured gate_decision event. HITLSequentialAgent must check the previous phase's outcome: an "exhausted" ideation_loop halts the workflow with a clear terminal event (autonomous) or pauses (hitl_enabled); an "exhausted" paper_writing_loop lets the run finish but tags state["manuscript_status"]="DRAFT_UNVERIFIED" and says so in the final event.

S0-2 Honest stages: StageOrchestratorAgent must set stage status to "completed" only if state["implementation_loop_outcome"]=="approved"; otherwise "completed_unverified". The stage dict gains a "status" field (keep "completed" bool for backward compat, derived). The stage_reflector prompt receives unverified stages flagged, with instruction to propose remediation or declare the stage unmeetable.

S0-3 No-progress guard: in StageOrchestratorAgent, after each orchestration iteration compute sha256 over (criteria met-bitmap, stage status vector, sorted (path, mtime, size) of files under workflow/ and results/). Two consecutive identical hashes -> re-run stage_reflector with an injected instruction "You MUST either propose a concrete stage modification/new stage or explicitly declare the remaining criteria unmeetable with reasons." Three consecutive -> terminate orchestration with a partial-results event (autonomous) or HITL pause. Emit progress_hash events.

S0-4 Sealed evolve evaluator: EvolutionLoopAgent must never read a score produced by the coding agent. After each mutation, the orchestrator itself runs `bash eval.sh` (cwd=workflow/, subprocess, timeout configurable default 600s, capture stdout/stderr). Score comes from workflow/results.json ONLY IF its mtime is later than the moment the orchestrator started eval; otherwise, or on nonzero exit / timeout, the child node gets score=None, status in {"failed","timeout"} and is committed as such (Database must accept score=None; samplers must skip None-score nodes). Remove the instruction telling Claude to run eval.sh and write results.json; the mutation prompt now says the orchestrator will evaluate.

S0-5 Intake router: before the workflow root runs, classify the user prompt into {replicate, novel, optimize, ambiguous} — implement as a cheap heuristic first (regex on replicate/reproduce/re-implement/faithfully implement -> replicate; maximize/optimize/improve the score/evolve -> optimize) with an optional single LLM call fallback behind a flag. If intent conflicts with research_mode: autonomous -> auto-switch the mode and emit an intake_decision event explaining it; hitl -> pause for confirmation. Ambiguous -> proceed with a warning event.

S0-6 Fix the cross-wired gate: rewrite prompts/base/implementation_review_confirmation.md from scratch. It must gate on the coding reviewer's actual output: exit=true iff the review contains no Blocking Issues; exit=false forwards the specific blocking issues verbatim as instruction to the coding agent; if the review states it could not be completed due to a tool failure, exit=true with a "review_degraded" note in the reason (a broken review tool must never trap the loop). No mention of novelty, MVPT, tiers, or ideation anywhere in the file.

S0-7 Conditional prompting: add a ToolAvailability probe at agent-graph construction (graphify importable? network enabled? pdflatex on PATH?). load_prompt gains the ability to strip named sections: wrap graphify guidance in prompt files with <!-- BEGIN:graphify --> ... <!-- END:graphify --> markers in coding_base.md and coding_review.md; assembler removes the block when graphify is unavailable. Delete the "You will be penalized if you don't read the Graphify report" line and any remaining mandatory graphify language; the retained (available-case) text must describe graphify as preferred-but-optional, consistent in BOTH files.

S0-8 Security sweep: in agents/claude_code/agent.py remove the hardcoded GitHub org/username and all auto repo-creation/push logic. Git behavior: always init + local commits; remote push only if config git.remote_url is set AND git.push=true; auth via env at push time, never written into .git/config (use a one-shot GIT_ASKPASS or http.extraHeader per command). Delete the mandatory `git push origin main` step from coding_base.md (local commit stays). setup_skills_directory: pin the skills repo to a SKILLS_REPO_SHA constant, clone once into ~/.archimedes/cache/skills/<sha>/ and copy from cache on subsequent runs. fetch_url: fix the DNS TOCTOU — resolve the host once, validate the IP, then connect to that IP (Host header preserved) or document/apply an equivalent single-resolution strategy. Unify Semantic Scholar access: one module-level client + one rate limiter used by BOTH research_ops and semantic_scholar_ops.

S0-9 Typed events: add to core/events.py event payload types (dataclasses or TypedDicts) and emit them where relevant: gate_decision{loop,outcome,reason}, stage_status{index,status}, eval_result{gen,score,status,duration_s}, progress_hash{hash,iteration}, intake_decision{detected_intent,selected_mode,action}. They must serialize into the existing event stream/session store.

S0-10 Sabotage test suite: tests/sabotage/ with 6 scenarios using mocked agents (no real LLM/network):
 (a) reviewer always rejects -> loop outcome "exhausted", stage "completed_unverified", no downstream phase treats it as verified;
 (b) novelty scorer always rejects -> workflow halts after ideation, planning never runs;
 (c) evolve child writes results.json with score 999 but eval.sh not executed by orchestrator-mock -> node committed with status failed / stale score rejected via mtime;
 (d) eval.sh sleeps past timeout -> node status "timeout", score None;
 (e) graphify unavailable -> assembled coding/review prompts contain zero occurrences of "graphify" (case-insensitive) and a mocked review completes;
 (f) prompt "Replicate tabular Q-learning on FrozenLake..." with research_mode="novelty" -> intake_decision event fires with action switch or pause.
Wire the suite into the CI workflow (.github/workflows/ci.yml) as a required job.
